01

Dual-Trigger Compaction Pipeline: Proactive Guard & Reactive Self-Healing

Context maintenance runs at critical boundaries of the agent execution loop. pi reconciles real API token usage telemetry with fallback heuristic accounting to drive two distinct compaction flows.

02

Session Tree & Context Projection: Disk Immutability vs Active View

In pi, session files are not flat chat logs. They are parent-pointer tree structures serialized in JSONL. Compacting never rewrites prior history on disk; instead, a pure projection function folds ancestor nodes into a clean context window.

03

Safe Cut-Point Slicing: Preventing Broken Tool Call Protocols

LLM tool calling enforces strict message pairing invariants: a tool_result cannot exist without its matching preceding tool_use. Naive token truncation reliably causes fatal API 400 crashes; pi enforces a defensive backward slicing algorithm.

04

Structured State & File Ops: Forgetting Details While Retaining Context

When dozens of turns are compressed, standard models easily lose track of files already modified or original constraints. pi extracts AST-level tool invocations and formats them into XML metadata tags accompanying a strict 6-part Markdown contract.

Architecture Trade-offs: Comparing Long-Horizon Memory Paradigms

Every context management strategy incurs costs across protocol reliability, token expenditure, and state consistency. The table below illustrates why pi settled on its folded tree architecture.

Protocol Invariant Safety Poor. Frequently truncates between toolCall and toolResult, causing fatal 400 Bad Request API errors. Fragile. Inserting arbitrary chunks out of sequential order destroys temporal and causal logic. Optimal. findCutPoint() strictly validates message pairing and anchors on clean turn boundaries.

Similarity match scores fluctuate; instructions without lexical match are omitted. Guaranteed. ## Goal and ## Constraints are enforced at the top of every generated checkpoint.
Session Branching & Undo Impossible. Linear history eviction is destructive and irreversible. Confusing. Modifying history corrupts shared vector embedding databases. Native. Every change is an immutable node in a parent-pointer tree; restoring any checkpoint is trivial.
Prompt Cache Efficiency Poor. Window shifting alters the token prefix on every single turn, wiping out cache hits. Worst. Dynamic fragment injection completely breaks prefix-based prompt caching. High. Maintains a stable ~20,000 token recency tail; summarization runs with cacheRetention: "none".
File Mutation Continuity Lost. Discarded tool calls erase knowledge of which files were already modified. Weak. Semantic search struggles to guarantee an exhaustive set of modified filenames. Deterministic. AST-extracted <read-files> and <modified-files> are permanently preserved.
Failure Recovery None. If an API call exceeds the context window, the agent hard crashes. Complex. Chunk re-ranking cannot rescue an overflowing generation turn. Automated. Reactive overflow compaction strips the broken response and retries via agent.continue().

Conclusion: For professional coding agents, context management cannot rely on statistical heuristics or lossy truncation; it requires a state-machine that respects the underlying LLM's protocol semantics.

Threshold Check & Cut-Point Discovery

/** Proactive budget check: has the safety reserve been breached? */
export function shouldCompact(
  contextTokens: number,
  contextWindow: number,
  settings: CompactionSettings
): boolean {
  if (!settings.enabled) return false;
  return contextTokens > contextWindow - settings.reserveTokens;
}

/** Backward slice search for valid cut boundary */
export function findCutPoint(
  entries: SessionEntry[],
  startIndex: number,
  endIndex: number,
  keepRecentTokens: number
): CutPointResult {
  const cutPoints = findValidCutPoints(entries, startIndex, endIndex);
  let accumulatedTokens = 0;
  let cutIndex = cutPoints[0];

  // Walk backward from newest, accumulating estimated tokens
  for (let i = endIndex - 1; i >= startIndex; i--) {
    const entryTokens = estimateEntryTokens(entries[i]);
    accumulatedTokens += entryTokens;
    if (accumulatedTokens >= keepRecentTokens) {
      cutIndex = findNearestSafeCutPoint(cutPoints, i);
      break;
    }
  }
  return { firstKeptEntryId, isSplitTurn, turnStartIndex };
}
