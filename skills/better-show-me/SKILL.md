# Better Show Me

把技术事实组织成清晰易读、便于定位和继续探索的呈现界面。内容紧扣主题；通过清晰分层、直观关联和按需展开来降低理解成本。 **以用户使用的语言呈现**。

先明确分析主题与观察范围，再提取足以支撑结论的关键事实。

## 解释性表达

- 面向具备通用技术背景、初次接触实现的读者：先讲清运行时的因果过程（谁在何时做什么、产生什么结果），再绑定代码符号与证据。
- 标题明确主题与章节重点，导语直接给出核心结论；正文用完整句子讲清因果与边界。
- 上下文交代：补充理解所需的背景与范围，确保脱离原对话分享时也能独立看懂。
- 术语首次出现交代角色，后文统一命名；图表节点保持精炼，文字展开详细因果。

## 输出构造

1. **主题与上下文**：明确分析主题与任务，交代必要的背景与范围。
2. **核心结论**：在开头导语直接给出核心结论与全局判断。
3. **主关系**：提炼核心逻辑（起点 → 关键跃迁 → 终态），选定最契合的原语直观表达；文字串起主体、条件与因果。
4. **辅助映射**：仅当另一个视角会改变结论或影响下一步时，再补充辅助原语。
5. **就近展开**：原因、规则与状态贴在对应节点或分支上，避免脱节。
6. **证据支撑**：关键结论紧邻代码符号、路径或局部切片。
7. **精准链接**：目标明确且有助于验证时才提供链接，不堆砌无效链接。
8. **实现附件**：用户需要完整代码时，作为独立附件交付。

## 任务方向

| 方向 | 核心诉求 | 常用组合 |
| --- | --- | --- |
| 理解现状 | 它由什么组成，如何工作 | 组件树、浅文件树、调用树、轻量时序、数据转换链、状态路径 |
| 理解变化 | 什么变了，会影响哪里 | 语义 Diff、行为前后、影响范围、局部代码 |
| 定位排查 | 预期与实际从哪里分叉 | 预期/实际分叉、故障因果链、状态快照、路径追踪 |
| 做出决策 | 方案差异与取舍是什么 | 对齐比较、权衡矩阵、方案骨架比较 |

仓库级请求以高层地图为入口，再围绕分析主题渐进展开。模块或逻辑级请求直接聚焦关键机制与证据。

## 原语与媒介

选择原语前先阅读 [references/primitive-system.md](references/primitive-system.md)；其中紧邻定义的示例既是选型依据，也是输出形态的语义基线。选定媒介后，再读取一份渲染指南：

- 文本输出：[references/rendering-text.md](references/rendering-text.md)
- HTML 输出：[references/rendering-html.md](references/rendering-html.md)，在关系结构确定后组合模板原语

## 质量标准

- 主视图在首屏或首段形成闭环，细节随后按需展开。
- 脱离原会话独立分享时，读者仅凭上下文与导语也能快速读懂。
- 逻辑关系比罗列清单更醒目，关键结论比视觉装饰更醒目。
- HTML 视觉主次分明且留白充分；降低阅读负担是指减少同一视区的焦点冲突，而非省略必要信息。
- 名称、状态与结论均有真实代码或数据支撑。
- 每个辅助视图必须提供一个独立的分析视角，否则并回主视图。
