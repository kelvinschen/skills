# Show Me 纯文本投影

纯文本与 HTML 使用同一份语义模型。文本依靠顺序、缩进、对齐和稳定符号建立主线。

主行只承载结构事实与决定性关系；证据和必要解释沿对应节点下沉。方括号不作为通用标注语法。

## 基础语法

- 粗体：结论、守卫、终态。
- 行内代码：标识符、路径、字段和值。
- 树线与缩进：层级。
- `→`：推进或数据流。
- `↑` / `↓`：事件上浮与数据下传。
- `+` / `-` / `~` / `=`：新增、删除、调整与保持。
- `@ path:line`：源码或文档证据，作为被证明事实的缩进附行；没有可靠行号时只写路径。

## 可寻址信息

使用 Markdown link 投影可寻址信息；链接文字承载最小的完整语义，不使用裸 URL 或“点击这里”等无语义锚点。目标不确定或跳转没有实际增益时保持纯文本。

## 信息预算

- 一行表达一个结构事实，最多再带一组同维度的原子关系；同一节点的一入一出可并列，但不再混入证据或解释。
- 去掉附加信息后，主结构仍须独立形成完整关系。
- 名称、操作符或控制流已经表达的含义直接删除，不再补充 `[守卫]`、`[I/O]`、`[只读]` 等标签。
- 改变路径、状态所有权、关键条件或结论的信息进入主结构；只负责证明的信息使用 `@` 下沉。
- 因果解释、修复方式或较长条件使用缩进子行，不做远距离行尾对齐。
- 删除后不改变理解、决策或下一步的信息不进入视图。

## 文本排布

| 表达家族 | 文本投影 |
|---|---|
| 层级 | 缩进与树线；职责、状态、源码锚点跟随节点 |
| 流转 | 编号步骤或单向箭头；标出关键跃迁与 I/O |
| 变化与决策 | 行首 Diff 符号或按共享维度对齐的 Markdown 表格 |
| 定位问题 | 从共同起点缩进展开首个差异，错误与证据贴在断点行 |

## 轻量 Mermaid

关系较少时使用缩进文本；空间关系成为主要问题时使用 Mermaid：`sequenceDiagram` 表达跨实体消息，`flowchart` 表达流程与数据流，`stateDiagram-v2` 表达有限状态，`erDiagram` 表达实体关系。

## UI 视觉

UI 空间关系属于 HTML 专属表达。文本输出使用组件树说明层级、状态所有权与交互方向。

## 完整实现附件

用户需要直接使用时，在解释之后提供标准 fenced code block，并标明文件路径、语言与运行前提。
