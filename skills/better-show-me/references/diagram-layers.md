# Layer Stack（分层堆栈）

**适用场景：** OSI / 协议栈、技术栈、抽象层、内存层级、CSS 层叠等具有明确上下级次序的模型。

**独有关系：** 回答“某项能力位于哪一抽象层、上下层如何依次承托”。如果重点是组件通信拓扑，使用 Architecture；如果各行表示责任主体而非上下层级，使用 Swimlane。

## 1. 布局与图元规范

- 使用 4～6 条等宽水平带自上而下堆叠；默认等高 56～72px，不因文案长短随意改变层高。
- 每层从左到右固定为：层号（`L5`）→ 层名称 → 右对齐说明。层号和说明使用 `.mono`。
- 用 `1px` hairline 分隔相邻层，整组保持单一外轮廓；采用统一底色或两种极弱的交替底色，不做彩虹分层。
- 在堆栈左侧放置方向轴，并明确两端语义，例如 `ABSTRACTION ↑` 与 `SILICON`；方向轴不能替代层号。
- 焦点色仅用于当前讨论的一层：`accent-tint` 填充 + `accent` 描边和层号，其他层保持中性。

## 2. 语义与顺序约束

- 相邻层必须存在可解释的依赖或抽象递进；不能仅因“都属于系统”就堆在一起。
- 层号连续递增或递减；确需跳层时，在名称或说明中解释缺失范围。
- 上下方向必须和用户问题一致：抽象程度、数据下沉或调用穿透只能选择一个作为主方向。
- 右侧说明只放该层的代表职责或实例，不重复层名称。

## 3. 复杂度预算

- 单图建议 4～6 层；超过 7 层时拆成总览与局部堆栈。
- 每层名称建议不超过一行，右侧说明控制在 2～4 个短语。
- 仅允许 1 个焦点层；多个重点应改用顺序标号或拆图。

## 4. 反模式

- 将没有层级关系的组件强行堆叠；此时应使用 Architecture。
- 每层使用不同高饱和颜色，导致颜色压过层级关系。
- 无原因地跳号、改变层高或交换上下方向。
- 用箭头画出大量跨层调用；Layers 表达层级，不承担调用拓扑。
