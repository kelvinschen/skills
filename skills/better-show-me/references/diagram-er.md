# ER / Data Model（实体关系模型）

**适用场景：** 概念或逻辑数据模型、API 资源关系、领域实体与基数，核心问题是“哪些实体以何种基数发生关系”。

**不适用：** 如果重点是物理表、SQL 类型、约束、索引以及列到列的外键连接，使用 Database Schema。

## 独有关系

- 关系线连接实体框而不是具体字段行，并在两端分别标出 `1`、`N`、`0..1`、`1..*` 等基数。
- 可在关系中部放置 `owns`、`contains`、`belongs to` 等短动词，帮助读者直接读出领域语义。
- 多对多关系需要显式关联实体时，将其画成独立 Join/Association Entity，不隐藏中间关系。

## 布局与几何

- 实体为两段式卡片：Header 包含类型与实体名，Body 仅列支撑关系理解的关键字段。
- 字段使用等宽字体；`#` 表示主标识，`→` 表示对其他实体的引用，但连线仍锚定实体边缘。
- 聚合根或当前讨论的中心实体可使用一处强调色；其他实体保持中性。
- 先绘制关系和基数标签，再绘制实体；相关实体靠近排列，优先让关系为直线或短正交折线。
- 实体高度跟随字段数量，不为视觉整齐强行填充无关字段。

## 复杂度预算

- 实体建议 ≤6，每个实体展示字段 ≤8，关系建议 ≤8。
- 超出预算时按 bounded context 或 aggregate 拆分，并保留跨图入口实体。

## 反模式

- 把 ER 画成物理数据库 Schema，塞入全部 SQL 类型、索引和约束。
- 基数只写一端，或同一张图混用不同的基数记法。
- 对几十个引用逐字段拉线，形成线团；应按实体关系聚类或拆图。
- 隐藏有业务意义的多对多关联实体。
- 为了等高而填充不影响关系理解的字段。
