# State Machine (有限状态机)

**适用场景：** 有限状态转换、生命周期管理（如订单状态、认证鉴权、任务生命周期、表单多步状态）。

## 1. 布局与图元规范

- **状态节点**：
  - 圆角矩形 `<rect rx="8">`，高度通常为 48~64px，底色 `#ffffff`，描边 `var(--color-ink)`。
  - 节点顶部带有小号大写 Tag（如 `STATE`，字号 7px，`JetBrains Mono`），主名称 13~14px 600（`Noto Sans`）。
- **起止点图元**：
  - **初始状态 (Start)**：实心墨色圆 `<circle r="6" fill="#2d3142"/>`。
  - **终止状态 (End)**：双环圆（外圈 `<circle r="8" fill="none" stroke="#2d3142" stroke-width="1.2"/>`，内圈 `<circle r="5" fill="#2d3142"/>`）。
- **流向与跃迁**：
  - 状态流转优先沿主方向（从左到右或从上到下）。
  - 跃迁连线标注触发事件与守卫：`event [guard] / action`（格式使用 `JetBrains Mono` 8px），省略不必要的部分。
  - 自环（Self-loop）从状态顶部弯出并重新接入。
- **视觉焦点**：
  - 焦点色（`accent` 橙色 `#eb6c36`）用于读者最应关注的重点状态（如最终完成态、核心处理中状态或关键熔断态）。

## 2. 状态机复杂度与约束

- 状态数建议 ≤8 个，跃迁连线数 ≤12 条。
- 超过复杂度上限时，拆分为父子子状态机或分离出异常熔断流。
- 严禁从所有状态画线指向同一个状态（如全局超时错误），应使用单独的文字注释代替。

## 3. 反模式 (Anti-patterns)

- 跃迁连线没有文字说明（必须写明是什么事件或条件触发了跃迁）。
- 状态过多且连线无规律相互穿插（应按生命周期阶段分区对齐）。
- 全图过多状态使用高亮强调（全图仅保留 1~2 处 `accent`）。
