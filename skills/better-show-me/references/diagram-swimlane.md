# Swimlane (跨角色流程泳道图)

**适用场景：** 跨团队流程、审批链、供应商交接、发布流程，以及需要回答“这一步由谁负责、责任在哪里转移”的工作流。

**不适用：** 服务消息的时间顺序优先用 Sequence；条件分支优先用 Flowchart；数据形态与处理阶段优先用 Data Flow。

## 1. 独有关系

- 一条轴表示流程推进，另一条轴表示唯一责任主体；每个步骤必须完全归属一条泳道。
- 穿越泳道边界的箭头就是 handoff，应原位标明交付物、触发条件或等待点。
- 泳道步骤数量无需相等；不要为了视觉均衡虚构工作。

## 2. 布局与图元规范

- 默认使用水平泳道、从左至右推进；角色较多而步骤较短时可旋转为垂直列。
- 左侧保留固定标签栏，泳道分隔线使用 `var(--color-rule)`；标签使用 `.mono`、8~9px 大写文字。
- 步骤使用 120~160px 宽、44~56px 高的圆角矩形，主标题 11~12px，可附一行交付物或命令。
- 先绘制泳道与连线，再绘制步骤节点；同泳道箭头尽量水平，handoff 使用短正交线或短斜线。
- 焦点色全图限 1~2 处，优先强调引入关键耦合、等待或发布风险的 handoff，而非装饰所有跨泳道箭头。

## 3. 复杂度预算

- 泳道建议 2~5 条，步骤建议 4~10 个，关键 handoff 建议不超过 4 个。
- 箭头频繁折返时先按执行顺序重排步骤；仍无法简化则拆成阶段图。

## 4. 反模式

- 泳道没有角色标签，或一个步骤跨越两条泳道。
- 用泳道替代时序协议图，却没有表达责任交接。
- 蛇形连线反复穿越边界，导致流程方向不可扫读。
