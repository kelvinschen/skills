# Tree / Hierarchy (单父节点层级树)

**适用场景：** 分类法、文件树、模块分解、决策拆解、技能树，以及任何“每个节点只属于一个父节点”的层级关系。

**不适用：** 多父节点、共享依赖或循环关系使用 Dependency；运行时通信使用 Architecture；步骤推进与状态转换使用 Flowchart 或 State。

## 1. 独有关系

- 除根节点外，每个节点恰好有一个父节点；兄弟节点共享同一条分支总线。
- 层级深度承载包含或分类语义，不允许跳级连接，也不借连线表达运行时调用。
- 叶节点可以用终端位置或更轻的描边表示，不必增加额外图标。

## 2. 布局与图元规范

- 默认根在上、子节点向下展开；宽度受限且层级较深时可旋转为从左至右。
- 节点使用 120~180px 宽、40~56px 高的圆角矩形；同层最多采用两种宽度。
- 连接器必须正交：父节点先垂直落到水平总线，再从总线垂直接入每个子节点顶边；禁止斜线。
- 先绘制连接器，再绘制节点；同层节点对齐，层间距保持一致。
- 焦点色只用于根节点或一个关键叶节点，二者不可同时强调。

## 3. 复杂度预算

- 最大建议深度为 4 层（根 + 3 层），每个父节点的直接子节点建议不超过 5 个。
- 超过预算时按子树拆图，并在父图保留可追踪的子树入口。

## 4. 反模式

- 一个节点连接多个父节点，或树中出现回环。
- 父节点越过中间层直接连接孙节点。
- 节点宽度随文本任意变化，或使用对角线制造视觉捷径。
