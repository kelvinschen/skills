# Deployment（部署拓扑）

**适用场景：** 软件实际运行在哪里：环境或网络 Zone、主机/VM/Pod/托管服务、部署制品版本、副本数以及协议端口。

**不适用：** 如果没有真实的放置决策、边界、副本数或关键版本，只需要说明组件如何通信，应使用 Architecture。

## 独有关系

- Deployment 回答“什么制品，以什么版本和副本数，运行在哪个基础设施节点与网络边界内”。
- 三层包含关系固定为 `Zone → Infrastructure Node → Artifact Chip`；Zone 必须代表真实环境或网络边界。
- 跨 Zone 的路径表示边界穿越，Zone 内路径表示内部调用；协议与端口是关系内容，不是装饰。

## 布局与几何

- Zone 使用大矩形、`rx=8`、浅填充、虚线边框，先于连线和节点绘制；标签放在左上角边界内侧，保留 8~12px 内边距，不用底色遮断边框。
- 基础设施节点使用 `rx=6` 卡片，左上角用 `POD`、`VM`、`MANAGED`、`CDN` 等矩形 Tag 表示类型。
- Artifact Chip 高约 24px，左侧写制品名、右侧写版本；同一节点可纵向堆叠 sidecar 等多个制品。
- 副本使用节点右上角 `xN` badge 表达，不要按副本复制节点。
- 连线使用正交圆角折线；跨 Zone 用 link 色，Zone 内用 muted，异步或复制链路用虚线。
- 协议与端口标签离开连线 4~8px；空间不足时调整路径或把线段拆开留出真实间隙，不用不透明底板盖线。
- 强调色最多两处，通常用于单点风险/新组件及其关键复制关系。

## 复杂度预算

- Zone ≤3，基础设施节点 ≤6，Artifact Chip ≤9，网络路径 ≤8。
- 超出预算时按环境拆分，不把 staging 与 production 混在一张图中。

## 反模式

- 给逻辑架构补几个 hostname 就称为部署图。
- Zone 只用于排版、没有实际边界语义。
- 制品没有版本，网络路径没有协议或端口。
- 用云厂商图标代替可识别的节点名称。
- 为每个副本画一个相同节点，或在一张图混合多个环境。
