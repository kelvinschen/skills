# Dependency Graph（依赖图）

**适用场景：** 包、模块或服务之间的依赖方向，尤其是需要表达**多父节点汇聚**或**循环依赖**时。

**不适用：** 如果每个节点只有一个父节点且不存在回边，使用 Tree；如果重点是运行时通信、协议或边界，使用 Architecture。

## 独有关系

- 边表示“依赖方 → 被依赖方”，方向必须在全图一致。
- 依赖图应至少揭示一种 Tree 无法承载的结构：共享依赖的 fan-in，或一个被明确标出的 cycle。
- 每个节点右上角可显示 `N in`，表示有多少节点依赖它；最高 fan-in 节点是结构焦点，但不额外放大。

## 布局与几何

- 按依赖深度自上而下分 rank，通常间隔约 100–120px；正常边只向下或在同一 rank 内横向移动。
- 节点使用约 `160×56`、`rx=6` 的矩形；内部包、外部依赖和叶节点使用不同的中性填充或边框。
- 先绘制连线再绘制节点；非同轴连接使用正交圆角折线，多条边进入同一侧时锚点间距至少 12px。
- 只允许一条强调色回边：从外侧绕过节点栈、虚线 `5,4`、标记 `CYCLE`；不得穿过无关节点。

## 复杂度预算

- 节点 ≤9，边 ≤14，rank ≤4，突出 cycle ≤1。
- 超出预算时将同类叶节点折叠为带数量的聚合节点，并明确写出省略数量。

## 反模式

- 把单父、无环数据强行画成依赖图，而不是 Tree。
- 不分 rank 的 hairball，或除 cycle 外仍有向上回折的边。
- 按文件逐个建节点；节点粒度应是能形成稳定依赖边界的包、模块或服务。
- 省略 fan-in，或同时强调多个 cycle，使结构焦点失效。
- 外部依赖不写版本、注册表或来源。
