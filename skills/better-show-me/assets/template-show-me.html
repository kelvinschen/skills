方案决策：中心注册表是当前约束下的最优修复位置

它在同一入口完成 schema 声明、类型收窄和失败记录，下游组件无需重复处理开放 payload。

当前约束时间线局部 Switch中心注册表Raw Event 兜底
payload 必须先校验渲染时才发现入口处完成未经校验进入 UI
新事件只声明一次类型与渲染分别修改schema 驱动解析下游持续处理 unknown
失败需要可观测容易落入 default统一记录原因弱化类型契约

选择中心注册表。校验、类型收窄和失败观测集中在同一个边界，页面与卡片不再重复防御开放 payload。

适用边界若产品允许未经校验的动态事件直接进入 UI，则需要重新评估 Raw Event 方案。

schema 注册与解析

const eventRegistry = createRegistry({
  message: messageSchema,
  agent_status: agentStatusSchema,
  skill_result: skillResultSchema,
});

export function parse(raw: RawEvent): SessionEvent {
  const schema = eventRegistry[raw.type];
  if (!schema) return unknownEvent(raw);
  return schema.parse(raw.payload);
}
